# v0.1.0 Release Checklist

Status: preparing `v0.1.0-rc1`.

Release freeze: no new major visualization/debugging capability before v0.1.0.
Only release blockers, correctness fixes, integration fixes, and release hardening are allowed.

Each item must be marked `PASS`, `FAIL`, or `N/A` with a reason before the release candidate is accepted. An unchecked item is not a pass.

## Engineering

- [ ] PASS: `npm test` completes with zero failures; FAIL: any Vitest test fails.
- [ ] PASS: `npm run typecheck` exits successfully; FAIL: TypeScript reports an error.
- [ ] PASS: `npm run build` creates a production `dist/`; FAIL: any build entry fails.
- [ ] PASS: manifest and package versions match `0.1.0`; FAIL: either version differs.
- [ ] PASS: the generated package contains every declared entry file; FAIL: any declared file is missing.

## Privacy / permissions

- [ ] PASS: `PRIVACY.md` matches the code's local processing and persistence behavior; FAIL: any claim contradicts runtime behavior.
- [ ] PASS: permissions are limited to the documented Side Panel, scripting, and LeetCode host access; FAIL: an unnecessary permission is present.
- [ ] PASS: no runtime code sends code, testcase, or trace data to a backend or analytics service; FAIL: an undocumented transmission exists.
- [ ] PASS: Store privacy and permission drafts are complete; FAIL: a required justification is missing.

## Fresh-install UX

- [ ] PASS: a fresh install opens an actionable Side Panel state; FAIL: a user sees only an unexplained blank or spinner.
- [ ] PASS: non-LeetCode, missing-editor, missing-testcase, and unsupported-language states explain the next action; FAIL: any state is silent or misleading.
- [ ] PASS: the Python-only boundary is visible; FAIL: the UI implies other languages are supported.
- [ ] PASS: the local-processing disclosure is available without blocking normal use; FAIL: it is absent or modal on every launch.

## Runtime smoke

- [ ] PASS: toolbar, reload, tab-switch, and Side Panel reopen flows work; FAIL: any lifecycle flow loses ownership or becomes unusable.
- [ ] PASS: fixed array, linked-list, tree/recursion, matrix, and graph fixtures render; FAIL: any required fixture regresses.
- [ ] PASS: runtime error, trace limit, and local timeout retain captured prefix where available; FAIL: useful context is unnecessarily erased.
- [ ] PASS: local runtime status is not described as LeetCode judge status; FAIL: copy claims Accepted or TLE semantics.

## Accessibility

- [ ] PASS: controls are keyboard reachable with visible focus; FAIL: any release control requires a pointer or has no focus indication.
- [ ] PASS: status and Baseline/Current differences are understandable without color alone; FAIL: color is the only distinction.
- [ ] PASS: `button` and `details/summary` semantics remain usable; FAIL: an action is represented by non-semantic text or keyboard navigation is trapped.

## Security

- [ ] PASS: no remote executable code, secrets, broad host access, or privileged worker access is present; FAIL: any unresolved release blocker remains.
- [ ] PASS: content-script and page-bridge message boundaries are reviewed; FAIL: an unexpected message surface is unreviewed.
- [ ] PASS: the CSP and Pyodide packaging remain compatible with the release; FAIL: runtime requires an undocumented remote dependency.

## Store assets

- [ ] PASS: 16/32/48/128 PNG icons exist and are readable at their target sizes; FAIL: any required icon is missing or illegible.
- [ ] PASS: Store listing copy is factual and matches the shipped Python-only behavior; FAIL: copy makes unsupported solver, judge, or correctness claims.
- [ ] PASS: the selected screenshots show real UI and contain no private data; FAIL: any screenshot is fabricated, unreadable, or exposes sensitive information.

## Packaging

- [ ] PASS: `npm run release:check` validates the built package; FAIL: the gate reports an error.
- [ ] PASS: `npm run release:zip` creates a deterministic ZIP from `dist/` only; FAIL: the archive includes source/development roots or changes between identical builds.
- [ ] PASS: generated ZIPs are ignored by Git and the exact SHA-256 is recorded; FAIL: a generated artifact is committed or its provenance is unknown.
- [ ] PASS: dependency and package audit records runtime-reachable advisories and bundle footprint; FAIL: findings are unclassified.

## Submission

- [ ] PASS: the exact RC source SHA, version, ZIP filename, size, and SHA-256 are recorded; FAIL: any artifact cannot be reproduced.
- [ ] PASS: Chrome Web Store privacy, permission, listing, and distribution fields can be completed from repository drafts; FAIL: a field requires an invented claim.
- [ ] PASS: the upload ZIP is the exact validated artifact from the accepted RC; FAIL: a different or dirty-build ZIP is used.

## Post-submission

- [ ] PASS: support path and issue templates are published; FAIL: users have no documented reporting route.
- [ ] PASS: review outcome and submission metadata are recorded without changing the validated artifact; FAIL: release records are incomplete.
- [ ] PASS: follow-up work is tracked separately from the frozen v0.1 scope; FAIL: post-release features are mixed into the RC.
