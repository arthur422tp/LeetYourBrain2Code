# Task 1: Make Source Sync Follow the Visible Monaco Editor

**Files:**
- Modify: `src/page-bridge/leetcode-main-world.ts`
- Modify: `tests/compatibility/page-state-contract.test.ts`
- Optional refactor: `src/page-bridge/editor-highlight.ts`

## Problem

Current source extraction chooses from `monaco.editor.getModels()` by language only:

```text
all Monaco models
→ matching selected language
→ Python fallback
→ first model
```

This can select a hidden/stale Python model instead of the editor the user is visibly editing.

Editor replay already has stronger ownership semantics because it uses visible Monaco editors and their attached models.

## Required behavior

Preferred selection order:

```text
visible Monaco editors
→ their attached models
→ selected language match
→ Python match
→ deterministic fallback only when no visible editor API is available
```

Requirements:

- prefer a model attached to a visible editor;
- reject hidden/disconnected editor DOM nodes;
- preserve unsupported-language reporting;
- do not require LeetCode Run/Submit;
- do not break environments where only `getModels()` is available;
- keep source extraction deterministic.

If practical, extract/reuse a shared visibility helper instead of duplicating two subtly different definitions.

- [ ] Add a compatibility regression with two Python models:
  - hidden/stale Python model with old source;
  - visible Python editor with current source.
- [ ] Assert `extractPageState(...).code` returns the visible editor source.
- [ ] Add a disconnected/hidden editor case.
- [ ] Preserve existing selected-language behavior.
- [ ] Run:

```bash

npm test
npm run typecheck
```

- [ ] Commit:

```bash
git add src/page-bridge/leetcode-main-world.ts src/page-bridge/editor-highlight.ts tests/compatibility/page-state-contract.test.ts
git commit -m "fix: prefer visible monaco source model"
```

Omit `editor-highlight.ts` if unchanged.

# Task 2: Correct Diagnostic Unknown/Unavailable Semantics

**Files:**
- Modify: `src/sidepanel/diagnostics.ts`
- Modify: `src/sidepanel/bootstrap.ts`
- Modify: `tests/sidepanel/diagnostics.test.ts`
- Modify: `tests/sidepanel/bootstrap.test.ts`

## 2A. Manifest version

Current environment collection may correctly produce:

```text
manifestVersion = unavailable
```

but snapshot collection converts the missing value to `0`.

Required behavior:

```text
manifest: unavailable
```

not:

```text
manifest: 0
```

Recommended type change:

```ts
manifestVersion: number | "unavailable";
```

through the final `DiagnosticSnapshot` boundary.

The formatter should format either the positive integer or `unavailable`.

## 2B. Active-tab ownership

When Chrome integration exists but ownership has not resolved yet:

```text
ownershipState === null
```

must produce:

```text
active_tab_owned: unavailable
```

not `false`.

Required projection:

```ts
!hasActiveTabSource || ownershipState === null
  ? "unavailable"
  : ownershipState.kind === "leetcode"
```

The distinction matters in public support reports:

- `false` = ownership is known and not LeetCode;
- `unavailable` = ownership has not been established.

- [ ] Add formatter test for unavailable manifest.
- [ ] Add bootstrap test for unresolved ownership.
- [ ] Verify non-LeetCode paused ownership still reports `false`.
- [ ] Verify active LeetCode ownership still reports `true`.
- [ ] Run:

- [ ] Commit:


# Release-Acceptance Definition of Done

v0.1.1 is accepted only when:

1. source extraction prefers the visible Monaco editor model;
2. hidden/stale Python Monaco regression is covered;
3. compatibility suite remains green;
4. missing manifest version reports `unavailable`, not `0`;
5. unresolved tab ownership reports `unavailable`, not `false`;
6. non-LeetCode ownership still reports `false`;
7. active LeetCode ownership still reports `true`;
8. README does not call v0.1.1 stable before release acceptance;
9. CHANGELOG does not imply an unpublished v0.1.1 is shipped;
10. all automated gates pass;
11. Release artifact workflow has a successful real run;
12. v0.1.1 ZIP and SHA-256 are produced from the exact release commit;
13. checksum is verified;
14. real Side Panel smoke is complete;
15. diagnostic privacy is manually verified with recognizable values;
16. toolbar/Side Panel lifecycle is manually verified;
17. the exact accepted artifact is uploaded to Chrome Web Store;
18. publication is confirmed;
19. README/CHANGELOG are then promoted to stable v0.1.1;
20. no new debugger capability was added during the correction.
